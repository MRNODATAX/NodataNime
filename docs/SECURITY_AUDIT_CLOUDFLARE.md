## 3. Tanya Jawab Keamanan (Security Q&A)

**Q1: Mengapa celah `redirect: "follow"` pada `/api/anime/stream-proxy` tergolong High meskipun sudah ada allowlist domain?**
> **Jawaban:** Karena `isAllowedStreamUrl()` sebelumnya hanya memeriksa URL awal. Apabila salah satu domain pada allowlist (terutama `pixeldrain.com` yang mengizinkan unggahan publik atau endpoint yang memiliki open-redirect) mengembalikan respons HTTP `302 Found` menuju `http://169.254.169.254/latest/meta-data/` atau layanan internal `http://127.0.0.1`, `fetch()` bawaan Node/Undici otomatis mengikuti redirect tersebut tanpa memeriksa ulang host tujuan. Dengan `redirect: "manual"` di `fetchWithSafeRedirects()`, setiap lompatan redirect diperiksa ulang terhadap allowlist sebelum request berikutnya dikirim.

**Q2: Bagaimana penyerang bisa melakukan XSS melalui proxy video, dan bagaimana tambalannya menghentikannya?**
> **Jawaban:** Sebelumnya `streamProxy.js` meneruskan header `Content-Type` dari server hulu apa adanya. Jika file di `pixeldrain.com` sebenarnya berisi dokumen `text/html` atau `image/svg+xml` yang mengandung `<script>`, maka ketika korban membuka `/api/anime/stream-proxy?url=...`, skrip tersebut dieksekusi langsung di bawah origin domain NodataNime sendiri (dapat membaca `localStorage` koleksi/riwayat tontonan). Kini `isSafeMediaContentType()` menolak seluruh MIME non-media dengan HTTP `415`, ditambah header `X-Content-Type-Options: nosniff` dan `Content-Security-Policy: default-src 'none'; media-src 'self'; sandbox`.

**Q3: Mengapa fungsi `esc()` (HTML escaping) saja tidak cukup melindungi `<iframe src>` dan `<a href>` dari XSS?**
> **Jawaban:** Fungsi `esc()` hanya menyandikan karakter `& < > " '`, sedangkan payload `javascript:alert(document.domain)` tidak membutuhkan satupun karakter tersebut! Oleh sebab itu kita menerapkan pertahanan tiga lapis: (1) `sanitizeHttpUrl()` di server membuang semua URL non-`http(s)`, (2) `safeUrl()` di browser memvalidasi ulang skema URL sebelum masuk ke DOM, dan (3) header `Content-Security-Policy` (`script-src 'self'; frame-src https:`) + atribut `sandbox` pada `<iframe>` memblokir eksekusi skrip inline di tingkat mesin browser.

**Q4: Apakah penerapan `Content-Security-Policy` ketat memengaruhi Live Preview Arena, PWA, font Google, atau pemutaran video?**
> **Jawaban:** Tidak sama sekali. Seluruh inline handler `onerror=` pada gambar telah diganti dengan global event listener JS (`document.addEventListener("error", ..., true)`), sehingga `script-src 'self'` berjalan mulus tanpa satu pun error konsol. Direktif `style-src` dan `font-src` mengizinkan Google Fonts (`Outfit` & `Plus Jakarta Sans`), `media-src` dan `img-src` mengizinkan CDN video/poster anime, `worker-src 'self'` & `manifest-src 'self'` menjaga PWA tetap aktif, dan `frame-ancestors 'self' https://*.e2b.app https://*.arena.ai https://arena.ai` menjaga iframe Live Preview tetap dapat ditampilkan.

**Q5: Apakah ada item yang berada di luar kode repositori (`NEEDS-VALIDATION`)?**
> **Jawaban:** Sesuai disiplin `cloudflare/security-audit-skill`, satu item dicatat sebagai `needs_validation` berisiko rendah (`nodatanime:vercel-edge:waf-and-deployment-protection-check`): karena Vercel Serverless menjalankan memori terpisah antar-instans saat trafik melonjak tinggi, Anda dapat mengaktifkan **Vercel Firewall / Attack Challenge atau Rate Limiting Rule** secara opsional di Dashboard Vercel pada rute `POST /api/community/messages` dan `GET /api/anime/stream-proxy` sebagai pelapis tambahan di tingkat CDN Edge.
